# ReaScript API lookup

REAPER's API has ~1200 Lua-callable functions with irregular signatures
(multiple return values, 0-based indices, out-strings passed as dummies).
Guessing from memory is the main source of bridge bugs, so check every
`reaper.*` call you write against the bundled help.

## Look things up

The help file is `references/reascripthelp.html` (1.5 MB, generated by
REAPER 7.80 on this machine, including the installed SWS extension). Don't
read it directly — query it with the script, which prints only the Lua
flavour:

```bash
S=.claude/skills/reascript-api/scripts/reascript_lookup.py
python3 $S GetTrack TrackFX_GetCount          # exact names (case-insensitive, "reaper." prefix ok)
python3 $S -s '^TrackFX_.*Param'              # regex over names
python3 $S -s 'loudness|LUFS' -d              # also search descriptions
```

Exact lookup prints the Lua signature and description; a typo gets "Did you
mean…" suggestions and exit code 1. Search prints name + signature, 40 hits
max (`-n` to change). Lua built-ins like `gfx.*`, `atexit`, `defer` are
included under their own names (`gfx.rect`).

Typical flow: search by concept → exact lookup of the candidates → write the
call exactly as the signature says (argument order, which values come back).

If REAPER was updated and a function is missing, ask the user to regenerate
the help (Help → ReaScript documentation; REAPER writes it to
`$TMPDIR/reascripthelp.html`) and copy it over `references/reascripthelp.html`.

## Pitfalls worth checking on every call

**Handles can be nil.** `GetTrack`, `GetMediaItem`, `GetTake`, `GetSelectedMediaItem`,
`GetMediaItemTake`… return nil for an out-of-range index, an empty item, etc.
Passing nil on crashes the call with "expected MediaTrack*". Check right after
fetching; for a handle you kept around, `reaper.ValidatePtr2(0, ptr, "MediaTrack*")`.
In the MCP bridge, resolve tracks with `get_track(p, key)` /
`get_numbered_track(p, key)` instead of `GetTrack` — they handle -1 = master
and return an error string.

**Indices are 0-based, the master is separate.** Tracks, items, takes, FX, sends,
markers-by-enum all start at 0. `GetTrack(0, i)` never returns the master;
use `GetMasterTrack(0)`. Lua tables you build are still 1-based.

**Multiple returns, retval first.** Many functions return `retval, value…`:
`local ok, name = reaper.GetTrackName(tr)`;
`local ok, s = reaper.GetSetMediaTrackInfo_String(tr, "P_NAME", "", false)`.
Out-string arguments in the C signature become return values in Lua; you
still pass a placeholder (`""`) where the Lua signature shows a parameter.

**Numbers.** `Get*Info_Value` always returns a float (`B_MUTE` → 0.0/1.0).
Lua 5.4 distinguishes integers and floats: `4/2` is `2.0`, use `//` or
`math.floor` for integers (JSON encoders and `string.format("%d")` care);
`math.floor` returns an integer.

**Undo.** Generic ReaScript: `Undo_BeginBlock()` … `Undo_EndBlock("desc", -1)`,
always paired. In *this repo's bridge* the rule is different — simple edits
are recorded by the dispatcher via `UNDO_POINT_COMMANDS`, item/MIDI edits also
need `UNDO_ITEM_COMMANDS` (undo blocks don't capture MIDI), and only batch
track/FX/routing handlers use their own block. See CLAUDE.md before adding one.

**Refresh.** Pair `PreventUIRefresh(1)` with `PreventUIRefresh(-1)`; after
structural changes call `UpdateArrange()` (and `TrackList_AdjustWindows(false)`
after adding/removing tracks).

**MIDI.** Positions are PPQ, not seconds — convert with
`MIDI_GetPPQPosFromProjTime(take, t)`. For many inserts pass `noSort = true`
to `MIDI_InsertNote`/`MIDI_InsertCC` and call `MIDI_Sort(take)` once at the end.

**Extension functions may be absent.** Names with prefixes like `NF_`, `BR_`,
`SNM_`, `CF_`, `JS_`, `ImGui_` come from SWS / js_ReaScriptAPI / ReaImGui.
They're in this help only because SWS is installed here; guard with
`reaper.APIExists("NF_AnalyzeTakeLoudness")` and return a clear error otherwise.

**Lua 5.4 language changes.** `unpack` → `table.unpack`; no `setfenv`;
`#t` is undefined for tables with holes. The bridge forbids `load`, `dofile`,
`loadstring` (static dispatch only).

**Debugging.** `reaper.ShowConsoleMsg(tostring(x) .. "\n")` prints to REAPER's
console; after editing the bridge the user has to re-run the script in REAPER.
